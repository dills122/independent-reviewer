# OpenRouter TypeScript SDK compatibility spike

## Decision

Do not migrate production transport to `@openrouter/sdk@1.2.110` yet. Keep the
current `ReviewProviderV1` adapter and orchestrator retry ownership. SDK was
exact-pinned for this compatibility spike, then removed when decoder-only work
pivoted to `eventsource-parser`; retain these findings as migration evidence.

Main blocker: direct SDK declarations fail under this repository's TypeScript
6.0.3 and Node 24.13.3 types. SDK `EventStream<T>` overrides
`ReadableStream<T>[Symbol.asyncIterator]` without the now-required
`Symbol.asyncDispose`, producing TS2416. `skipLibCheck` would hide this and other
dependency declaration defects, so the spike does not change that project gate.
The same incompatible declaration exists in inspected `1.2.2`, so selecting that
older release is not a supported fix.

## Sources and exact package inspection

- Official SDK overview describes an OpenAPI-generated, type-safe client and
  `chat.send`: https://openrouter.ai/docs/client-sdks/typescript/overview
- Official Chat Completions reference defines streaming/non-streaming requests,
  routing fields, and marks `max_tokens` deprecated in favor of
  `max_completion_tokens`:
  https://openrouter.ai/docs/api/api-reference/chat/create-a-chat-completion
- Official routing reference defines provider allowlisting, fallback,
  `require_parameters`, price, data-collection, and ZDR controls:
  https://openrouter.ai/docs/guides/routing/provider-selection
- Official error reference documents errors embedded after generation begins:
  https://openrouter.ai/docs/api_reference/errors-and-debugging
- Spike package: `@openrouter/sdk@1.2.110`, generated by Speakeasy 2.914.0. Exact
  declarations and emitted runtime were inspected before removing the package;
  no package source was edited.

## Offline results

### Request parity

Deterministic mock transport confirms SDK sends the same policy semantics:
explicit model and messages, non-streaming mode, strict JSON Schema, provider
order/allowlist/fallback, data-collection denial, price ceilings,
`require_parameters`, ZDR, disabled context compression, bearer authentication,
and `x-openrouter-cache: false`.

Wire identity is not byte-compatible. SDK sorts fields by generated schema order,
serializes `max_price` values as strings, and adds `Accept`, empty `Cookie`, and a
versioned `User-Agent`. Any future migration must generate `wireBodyDigest` from
the SDK's outbound serializer, bump provider-policy version, and explicitly
define whether SDK-added public headers belong in
`credentialFreeWireRequestDigest`.

Installed declarations expose both `maxTokens` and `maxCompletionTokens`. The
former preserves current `max_tokens` semantics but its declaration text and
official API reference mark that wire field deprecated; generated declarations
do not carry a TypeScript `@deprecated` tag, so configured checks emit no warning.
A migration should deliberately select `max_completion_tokens` and treat the
resulting wire/audit change as a policy-version change rather than silently
keeping the deprecated spelling.

### Retry, timeout, and error behavior

SDK default for Chat Completions is backoff retry of connection errors and `5XX`
responses. Passing `{ strategy: "none" }` at client and call levels produces
exactly one mock request for HTTP 500. Both settings should remain defensive
because generated code selects per-call, then client, then a retrying default.

SDK accepts a per-call `AbortSignal` and timeout option. Its HTTP layer applies
timeout signal before fetch, but product still needs a test proving abort remains
active while a response body stalls. Existing product classification must remain:
a possibly submitted header/body/network timeout is `TRANSPORT_UNCERTAIN`, never
an automatically retried definite provider failure.

Typed SDK HTTP errors retain status, body string, headers, and `rawResponse`.
Successful `ChatResult`, however, strips unknown fields and does not expose the
top-level OpenRouter `provider` extension observed by current live responses.
Therefore SDK result objects cannot replace product raw-envelope evidence,
provider route recording, or forward-compatible usage parsing. A production
migration needs a custom HTTP client/response clone with the existing 8 MiB cap,
credential redaction, and raw-body persistence before SDK parsing. Response
hooks run before parsing but do not themselves impose a byte cap.

### Product-owned invariants

Keep outside SDK: routing/privacy policy construction; disabled response caching;
deterministic audit identity; shared pacing; orchestrator retry admission and
attempt ledger; route reordering; timeout uncertainty; bounded response capture;
HTTP-200 embedded error detection; raw error evidence; credential redaction and
reflection rejection; usage normalization; finish/model/content validation; and
structured JSON parsing.

SDK may replace endpoint/auth/header mechanics, generated request serialization,
dispatch, and OpenAPI types only after declaration and raw-evidence gaps close.

## Streaming and progress guard: separate decision

`chat.send` supports SSE and exposes an async stream, while HTTP and SDK hooks can
observe requests/responses. This is enough for a later prototype that counts
whitespace-only deltas and cancels stalled output. Offline mock SSE confirms a
whitespace delta is visible and breaking iteration cancels the upstream stream.
It is not proof of safe product behavior: cancellation can omit final
usage/provider metadata, raw SSE capture needs its own byte bound, and cost
remains uncertain after submission.

Most importantly, SDK adoption alone does not fix runaway whitespace. That
behavior originates in upstream provider constrained decoding. Streaming only
offers an earlier observation/cancellation point. Production remains
non-streaming until a separate guard decision defines thresholds, false-positive
handling, evidence retention, and ledger/cost semantics.

## Exit criteria for revisiting migration

Revisit when an exact SDK release compiles with project TypeScript/Node types
without `skipLibCheck`, or when project accepts a narrow upstream-compatible type
fix. Then implement raw bounded capture around SDK transport, prove body-phase
abort classification, bind audit bytes to SDK serialization, rerun all existing
provider parity cases, and only afterward consider production adoption.
