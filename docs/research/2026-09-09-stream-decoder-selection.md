# Streaming decoder selection

## Decision

Use exact-pinned `eventsource-parser@4.1.0` for SSE framing. Do not use
`@openrouter/sdk`, OpenAI SDK, or Vercel AI SDK solely as a decoder.

This keeps ownership narrow: library converts incremental UTF-8 text into SSE
events; Independent Reviewer retains HTTP, request identity, OpenRouter event
JSON, raw evidence, byte limits, validation, timeout classification, pacing,
retries, usage, and cost uncertainty.

## Candidate comparison

| Candidate | Strength | Mismatch |
| --- | --- | --- |
| `@openrouter/sdk` | Official OpenRouter client; streaming async iterable | TypeScript 6 declaration failure; strips provider/unknown response fields; changes transport and audit bytes |
| OpenAI SDK | OpenRouter-supported integration; mature async streaming and cancellation | Full OpenAI-compatible client, not standalone decoder; OpenRouter extensions remain outside its contract |
| Vercel AI SDK | OpenRouter-supported provider; high-level text/event streams | Adds application/agent abstractions and response transformations beyond this CLI boundary |
| `eventsource-parser` | Focused WHATWG SSE parser; zero runtime dependencies; explicit parser buffer cap | Not OpenRouter-specific; local code must still validate JSON chunk shapes and `[DONE]` |

OpenRouter lists both OpenAI SDK and Vercel AI SDK as supported integrations, and
documents Vercel's `streamText` path. OpenAI's Node SDK documents async iteration,
loop-break cancellation, and explicit abort for Chat Completions. Those are sound
choices when adopting their full client boundary, but they are unnecessarily
broad for preserving this adapter's exact OpenRouter policy and evidence.

`eventsource-parser` is source-agnostic by design. Version 4.1.0 requires Node
22.12 or newer, has no runtime dependencies, compiles directly with project
TypeScript 6.0.3/Node 24.13.3 types, supports callback and TransformStream forms,
and exposes `maxBufferSize` for incomplete lines/events.

## Implemented offline seam

`decodeOpenRouterSseV1` wraps parser callback API and adds product boundaries:

- fatal UTF-8 decoding across arbitrary byte splits;
- exact raw-chunk observation before decoding;
- separate 8 MiB total-response and 1 MiB partial-event defaults;
- JSON parsing without claiming schema validity;
- explicit terminal `[DONE]` requirement;
- stable error codes for configuration, UTF-8, SSE, JSON, event-size,
  response-size, and truncated-stream failures; and
- upstream cancellation when consumer stops iteration.

Deterministic tests cover CRLF and LF framing, comments, multi-line data, a
multi-byte code point split across chunks, malformed SSE/JSON, both bounds,
missing `[DONE]`, invalid UTF-8, exact raw chunks, and early cancellation.

## What this does not fix

Two different "decoders" matter here. Current production adapter requests
`stream: false` and parses one JSON HTTP body, so it has no client-side SSE
decoder in the failing path. Saved responses contain runaway whitespace inside
`choices[0].message.content`; therefore SSE framing did not create original
whitespace. Likely failure surface is upstream constrained token decoder.

Decoder sees whitespace already generated by provider. It cannot prevent
upstream constrained decoder from selecting grammar-permitted whitespace or
recover missing JSON fields. Value comes from making a later progress guard
reliable: observe deltas early, preserve partial raw evidence, and abort locally
when a calibrated JSON-aware threshold is crossed.

Follow-up implementation is specified in
[`2026-09-10-openrouter-whitespace-guard-plan.md`](../plans/2026-09-10-openrouter-whitespace-guard-plan.md).
It defines JSON string/escape state, a calibrated candidate threshold, distinct
guard failure, conservative missing-usage accounting, and endpoint-specific
retry. Cancellation still cannot be advertised as guaranteed billing termination.
